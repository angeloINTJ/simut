Este arquivo foi produzido para ser **lido por uma IA que irá cooperar com o humano** do projeto. Portanto:

1. **Nenhum achado deve ser implementado sem o humano aprovar.** Mudanças em firmware embarcado que rodam sob watchdog de hardware têm impacto de campo. Este documento **propõe**; humano **decide**; IA **implementa**.

4. **Jargão interno do projeto** está decodificado no §3. Não improvise interpretações — consulte o glossário.
5. **Cobertura de inspeção** está em §2. Achados sobre módulos inspecionados apenas parcialmente são marcados com `[amostragem]`; não tome esses como exaustivos.

### 1.2 O que está bem feito (a análise e o reviewer partem daqui)

A qualidade de engenharia *interna* é acima da média para um projeto single-author de Arduino. Registros que confirmam isso:

- **Wrap-safety de `millis()` consistente** — helpers `timeReached() / timeSince() / timeRemaining()` em `SystemDefs.h` (linhas 271–310), usados em dezenas de sites.
- **Layout binário verificado em tempo de compilação** — todos os `struct __attribute__((packed))` (config, users, history, log compacto, touch cal, sound cal, display offset, net/time overlay) têm `static_assert` travando o tamanho. Migrações versionadas (v12 → v13 → v14 → v15).
- **RAII guards espalhados corretamente** — `RenderGuard`, `ReadGuard`, `HeavyTaskGuard`, `WdtWindow`, `TraceScope`. Raramente vê-se isso feito certo em Arduino.
- **Primitivas de segurança sérias** — HMAC-SHA256 via BearSSL, `secureCompare()` constant-time, nonces de login com TTL, rate-limiter por IP, HKDF-like `deriveKeystream` para ofuscação de campos sensíveis, validação `isSafeUploadFilename` com blocklist de percent-encoding.
- **Forenses de crash** — black-box profiler por core, autópsia via `watchdog_hw->scratch[]`, `TraceScope` para rastrear módulo ativo, `_preBootSnapshotTaken` para não perder evidência no segundo boot.
- **Contratos cross-core sofisticados** — quiet mode cooperativo, lockouts IRQ-based, hard-reset de Core 1 como fallback. Tudo versionado nos comentários (`v3.24.9` → `v3.24.10` → `v3.24.11`).
- **Input validation centralizada** — `parseIntStrict`, `isValidName`, `isValidCfgString`, `isValidIpv4`, `isSafeUploadFilename`.

**Consequência para o reviewer:** o objetivo **não é reescrever**, é **organizar e reduzir atrito externo** (build, docs, split de arquivos gigantes, glossário) sem perder nenhuma dessas qualidades internas.

## 4. Achados P0 — resolver antes de qualquer refatoração maior

### 4.1 Sistema de build ausente

**Evidência:** `find` no diretório da fonte não encontra `platformio.ini`, `arduino-cli.yaml`, `CMakeLists.txt`, `Makefile`, `boards.txt`, `partitions.csv`. Apenas o `SIMUT.ino` existe, indicando uso provável de Arduino IDE.

**Problema:** binário não é reproduzível por terceiros. Alvo RP2040 com dual-core, watchdog, LittleFS, BearSSL embarcado, PIO custom — a matriz de versões de biblioteca que compila corretamente é **estreita**. Sem pin de versões, reinstalar o ambiente em máquina nova pode levar horas até achar a combinação.

**Ação proposta (implementação cooperativa IA ↔ humano):**

1. Humano informa: versão do core `arduino-pico` em uso, versão de cada biblioteca de `#include`, target board exato.
2. IA gera `platformio.ini` equivalente (PlatformIO é o padrão industrial mais robusto para RP2040). Conteúdo esperado:

```ini
; ============================================================================
;  platformio.ini — configuração de build reproduzível do SIMUT
;  Alvo: Raspberry Pi Pico W (RP2040), framework Arduino-Pico.
;  Qualquer mudança aqui precisa vir junto com um bump de versão em
;  SIMUT_VERSION (ver SystemDefs.h) para manter a trilha de auditoria.
; ============================================================================
[platformio]
default_envs = pico_w_release
src_dir      = SIMUT            ; mantém layout atual; .ino vira .cpp em build

[env]
platform         = https://github.com/maxgerhardt/platform-raspberrypi.git
framework        = arduino
board            = rpipicow
board_build.core = earlephilhower
upload_protocol  = picotool
monitor_speed    = 115200

; Flags comuns: otimização de tamanho + warnings elevados. -Wall/-Wextra expõem
; os `unused-parameter` residuais sem quebrar o build; -Werror fica OFF até o
; backlog de warnings ser zerado (ver §4.4).
build_flags =
    -Os
    -Wall
    -Wextra
    -Wno-unused-parameter
    -DSIMUT_BUILD_TIMESTAMP=$UNIX_TIME

; Libs travadas por commit/versão. TODA biblioteca transitiva aqui — o core
; Arduino-Pico já traz BearSSL, mas o resto precisa ser explícito.
lib_deps =
    adafruit/Adafruit GFX Library @ ^1.11.9
    adafruit/Adafruit ILI9341 @ ^1.6.1
    PaulStoffregen/XPT2046_Touchscreen @ ^1.4
    knolleary/PubSubClient @ ^2.8
    ; ---- libs custom do autor (URL + commit SHA obrigatórios) ----
    ; https://github.com/<user>/OneWirePIO_RP2040#<sha>
    ; https://github.com/<user>/DS18B20PIO#<sha>
    ; https://github.com/<user>/DHT22PIO#<sha>
    ; https://github.com/<user>/BuzzerPIO_RP2040#<sha>

[env:pico_w_release]
build_type = release

[env:pico_w_debug]
build_type = debug
build_flags = ${env.build_flags} -DSIMUT_DEBUG_BUILD=1
```

**Critério de aceite:** em máquina nova, `pio run -e pico_w_release` produz um `.uf2` idêntico (bit-a-bit) ao último flash oficial do autor.

### 4.3 Código `TEST-ONLY` em release

**Evidência:** três sítios marcados pelo próprio autor:

- `SystemDefs.h:1085–1094` — enum `CMD_DBG_SENSOR_HISTORY_ALL`.
- `CommandManager.cpp:392` — parser marcado `TEST-ONLY — REMOVE BEFORE PRODUCTION`.
- `AppManager.cpp:1193–1234` — handler `case CMD_DBG_SENSOR_HISTORY_ALL`.

**Comentário do autor citando instruções de remoção**: *“Para remover: excluir este enum + parser + handler + chamadas relacionadas.”*

**Risco:** o comando permite zerar `provisionEpoch` de todos os sensores via CLI (USB ou Bluetooth autenticado). Em produção, um operador com acesso USB consegue fazer o histórico pós-reset parecer pré-reset. Não é *backdoor* crítico, mas é **superfície de ataque que já tem uma decisão documentada para não existir**.

**Ação proposta:** IA remove os 3 sítios em um único PR, com commit message que cita este §4.3. Incluir no PR um teste manual de não-regressão:

```text
# Checklist após remoção de CMD_DBG_SENSOR_HISTORY_ALL
- [ ] Build limpo sem warnings sobre enum não usado.
- [ ] `help` no CLI (USB e BT) não lista o comando.
- [ ] `conf sensor 0 history all` retorna CLI_UNKNOWN_CMD com log SYS_CLI.
- [ ] Nenhum outro case referencia CMD_DBG_SENSOR_HISTORY_ALL (grep).
- [ ] Nenhum handler web referencia a funcionalidade (grep provisionEpoch).
```

**Preservação:** nenhuma função pública é removida. Apenas um enum + um branch de parser + um branch de handler. Operação segura por construção.

## 5. Achados P1 — débito arquitetural relevante

### 5.1 `SystemDefs.h` é um *catch-all* de 1.342 linhas

**O que há dentro** (enumerado do próprio arquivo):

- Macros de limite de hardware (linhas 18–24).
- `enum MinMaxSlot`, constantes de boot/timing, rede, rate-limit, login, BT, CLI, web, AP, cursor (linhas 33–222).
- Helpers inline `safeCopy`, `timeReached`, `timeSince`, `timeRemaining` (237–310).
- Bitmasks de permissão (314–324).
- Enums `TraceModule`, `SensorType`, `TelemetryMode`, `TelemetryTransport`, `LanguageCode`, `LogCode` (332–542).
- Enums de UI `UiMode`, `GraphRange` (544–575).
- `struct SensorRecord`, `UserAccount`, `TouchCalData`, `DisplayOffsetData`, `CliConfigData`, `SystemConfig`, `WebConfigData`, `SetupFlagsData`, `NetworkTimeData` (577–784).
- Utilidades compartilhadas `dallasCrc8`, `isValidHistoryFileName` (791–803).
- `struct ScanResult`, `SensorReading`, `UiEvent`, `GraphDataPackage`, `SystemStatusData` (805–933).
- `enum LogTagId`, helpers `tagStringToId`, `tagIdToString`, `struct CompactLogRecord` (946–1027).
- Arquitetura CLI inteira: `enum DemandType`, `struct CliDemand` (1034–1119).
- `struct BinaryHistoryRecord` com métodos `floatToI16`, `i16ToFloat`, `clear`, `toCsvLine` inline (1146–1225).
- Helpers de validação `parseIntStrict`, `isValidCfgString`, `isValidName`, `isSafeUploadFilename`, `isValidIpv4`, `isInRange` (1232–1343).

**Problema:** cada header de módulo faz `#include "SystemDefs.h"`, que por transitividade puxa tudo acima. Qualquer edição em qualquer seção invalida o cache de build do projeto todo. Segundo efeito: **contrato público do projeto é opaco** — novo contribuidor precisa ler 1.342 linhas para saber o que é API pública vs. detalhe de implementação.

**Ação proposta — split incremental, sem perder nenhum símbolo**:

Proposta de decomposição em 6 headers menores, com `SystemDefs.h` tornando-se um *facade* que reexporta tudo por `#include` (para não quebrar nenhum caller):

```
SystemDefs.h                 ← fica como facade (#include dos abaixo)
├── core/Limits.h            ← MAX_SENSORS, MOVING_AVG_WINDOW, SIMUT_VERSION, GRAPH_WIDTH, MinMaxSlot
├── core/TimingConfig.h      ← BOOT_*, WATCHDOG_*, NET_*, WDT_*, NTP_*, RATE_*, CLI_LINE_MAX, AP_*, CURSOR_*
├── core/TimeHelpers.h       ← safeCopy, timeReached, timeSince, timeRemaining
├── core/Permissions.h       ← PERM_* bitmasks, LogCode, LogTagId, TraceModule
├── data/Records.h           ← SensorRecord, UserAccount, SystemConfig, *OverlayData, BinaryHistoryRecord, CompactLogRecord, todos os static_asserts
├── ui/UiTypes.h             ← UiMode, GraphRange, ScanResult, SensorReading, UiEvent, GraphDataPackage, SystemStatusData
├── cli/CliTypes.h           ← DemandType, CliDemand
└── util/Validation.h        ← parseIntStrict, isValidCfgString, isValidName, isSafeUploadFilename, isValidIpv4, isInRange, dallasCrc8, isValidHistoryFileName
```

**Regra de migração obrigatória:** todo símbolo existente continua acessível pelo caminho antigo. Ou seja:

```cpp
/**
 * @file SystemDefs.h
 * @brief Facade de compatibilidade — mantém o include-point histórico.
 *
 * Este arquivo foi esvaziado na refatoração REF-SYSDEFS-SPLIT (§5.1 do
 * documento de análise v1). Os símbolos agora vivem em headers menores
 * sob core/, data/, ui/, cli/, util/. O facade existe para não quebrar
 * os dezenas de `#include "SystemDefs.h"` espalhados pelo projeto —
 * qualquer include histórico continua resolvendo todos os símbolos.
 *
 * Nenhum símbolo foi removido, renomeado ou teve semântica alterada
 * nesta refatoração. A amarração é puramente de organização de arquivos.
 */
```

### 5.4 `AppManager.h` força rebuild em cascata

**Evidência** (`AppManager.h:16–26`):

```cpp
#include <Arduino.h>
#include <vector>
#include "SensorManager.h"
#include "StorageManager.h"
#include "CommandManager.h"
#include "SystemDefs.h"
#include "DisplayManager.h"
#include "NetworkManager.h"
#include "WebManager.h"
#include "TelemetryManager.h"
#include "SoundManager.h"
```

**Problema:** `AppManager.h` incluído no `.ino` principal. Cada header incluído aqui é puxado transitivamente para qualquer TU que inclua `AppManager.h`. Edição em `WebManager.h` recompila `SensorManager`, `StorageManager`, etc.

**Ação proposta:** quebrar com *forward declarations* no `.h`, manter includes completos no `.cpp`. Os managers são membros por valor (`SensorManager _sensorMgr;`), então forward declaration simples **não** basta (o compilador precisa do sizeof). Alternativas:

**A — `std::unique_ptr` (mais limpo, aceita forward decl):**

```cpp
// AppManager.h — versão refatorada

#include <memory>          // para std::unique_ptr
#include <vector>
#include "core/Limits.h"   // só MINMAX_SLOT_COUNT + MAX_SENSORS
#include "cli/CliTypes.h"  // só CliDemand (parâmetro público de executeCommand)

/* Forward decls — evitam puxar toda a hierarquia de headers para cada
 * TU que só precisa ver a interface do AppManager. Cada Manager é
 * incluído por completo apenas em AppManager.cpp. */
class SensorManager;
class StorageManager;
class CommandManager;
class DisplayManager;
class NetworkManager;
class WebManager;
class TelemetryManager;
class SoundManager;
struct GraphDataPackage;

class AppManager {
public:

    void setup();
    void loop();

    bool isDisplayAlive();
    void restartDisplayCore();
    void pauseDisplayForFlash(bool lock);
    bool requestDisplayQuietMode(bool enable);
    void core0Yield();
    bool isUserInteracting() const;

private:
    std::unique_ptr<SensorManager>    _sensorMgr;
    std::unique_ptr<StorageManager>   _storageMgr;
    std::unique_ptr<CommandManager>   _cmdMgr;
    std::unique_ptr<DisplayManager>   _displayMgr;
    std::unique_ptr<NetworkManager>   _netMgr;
    std::unique_ptr<WebManager>       _webMgr;
    std::unique_ptr<TelemetryManager> _telemetryMgr;
    std::unique_ptr<SoundManager>     _soundMgr;

    // ... restante igual ao original, nenhuma função pública removida ...

```

E no `.cpp`:

```cpp
/* Construtor: heap allocation única no boot, antes do loop start.
 * Semântica idêntica ao `SensorManager _sensorMgr` original — só
 * muda o ponto de alocação (heap em vez de BSS). Custo: ~8 ponteiros

    _preloadHumMin = 1000.0f; _preloadHumMax = -1000.0f;

AppManager::~AppManager() = default;  /* tipos completos visíveis aqui */
```

**B — Manter por valor, aceitar o coupling** (status quo).

Recomendação: **B só enquanto o projeto couber num único contribuidor**; migrar para **A quando a colaboração IA ↔ humano começar a ser frequente**. Heap adicional é ~8 ponteiros × 4 bytes = 32 B, desprezível.

### 5.5 `Arduino String` em paths de rede/telemetria/CLI

**Evidência:** 252 ocorrências em `.cpp`. Distribuição:

| Arquivo | Usos |
|---|---:|
| `WebManager.cpp` | 75 |
| `DisplayManager.cpp` | 48 |
| `TelemetryManager.cpp` | 40 |
| `CommandManager.cpp` | 28 |
| `StorageManager.cpp` | 23 |
| `AppManager.cpp` | 19 |
| `NetworkManager.cpp` | 8 |
| `LogManager.cpp` | 7 |
| Outros | 4 |

**Bom:** o autor já removeu `String` de sites críticos (`CON-005a` nonce, `CON-005b` CliDemand, `TelemetryManager::buildPayload` usa `char[]` interno). O que sobra é **viável** mas não **crítico**.

**Recomendação:** não refatorar todos. Priorizar em ordem de risco:

1. **`LogManager.cpp` (7 usos)** — logger deve ser o que **menos** aloca. Alvos principais: `log(LogLevel, tag, code, String msg)` recebe `String` por valor, podendo ser `const char*` + `int context`. Conversões já existem (ver linha 1009 do `SystemDefs.h`, `extraMsg`).
2. **`TelemetryManager` (40 usos)** — `buildPayload` já usa buffer fixo, mas `attemptHttpUpload(String& payload, ...)` aceita `String&` na assinatura. Manter a assinatura (evita quebrar caller) mas internamente passar `payload.c_str()` e `payload.length()` para as libs HTTP.
3. **Resto** — deixar, custo-benefício baixo.

**Regra de ouro proposta:**
- `String` em parâmetro de interface pública: OK.
- `String` como *local temporário* dentro de loop: **não**.
- `String` em ISR ou timer callback: **nunca**.
- `String msg` em logger: **evitar**, preferir `const char*` ou `int context`.

### 5.6 `WebManager.cpp:2530` re-inicializa `LogManager` no handler HTTP

**Evidência:**
```cpp
void WebManager::handleApiClearLogs() {
    // ...
    LittleFS.remove(LOG_FILE_CURRENT);
    LittleFS.remove(LOG_FILE_OLD);
    // ...
    LogManager::instance().begin(true, LOG_DEBUG);  // ← linha 2530
    // ...
}
```

**Problema:** `begin()` é invocado num path não-boot. Pelo comentário em `LogManager.cpp:36–40`:
> *“Guard one-shot: performCrashAutopsy() roda uma única vez por sessão. `begin()` é chamado múltiplas vezes em runtime (clear log, web clear logs) — sem este guard, a 2ª autópsia re-dispararia HW WATCHDOG.”*

Ou seja, o autor **sabe** e tem guard. Mesmo assim, `begin()` fazendo reset de estado mid-HTTP é acoplamento estranho. **Ação proposta:** extrair a parte rotacional (`_currentLineCount=0`, criação de novo arquivo de log) para um método próprio:

```cpp
/**
 * @brief  Reset de contadores internos do logger após limpeza externa
 *         dos arquivos de log (p.ex. handleApiClearLogs).
 *
 * Substitui a chamada a `begin()` em sítios que não são boot. Não toca
 * em `_lockCb`, `_consoleSink`, `_epochFn`, `_saveToFile`, `_minSerialLevel`
 * — estes são configurados UMA vez no boot e nunca devem ser resetados
 * em runtime (senão o logger perde o sink CLI e as autópsias).
 *
 * @param  alsoClearPending  Se true, descarta logs ainda em _pendingLogs
 *                           antes de resetar contadores (use quando o
 *                           caller intencionalmente apagou os arquivos).
 */
void LogManager::resetAfterExternalWipe(bool alsoClearPending) {
    mutex_enter_blocking(&_logMutex);
    if (alsoClearPending) {
        _pendingCount = 0;
        _pendingOverflow = 0;
    }
    _currentLineCount = 0;
    _currentLogFileName = "";
    if (_currentLogFile) _currentLogFile.close();
    mutex_exit(&_logMutex);
}
```

E no `WebManager.cpp`:
```cpp
LogManager::instance().resetAfterExternalWipe(/*alsoClearPending=*/true);
```

**Preservação:** `begin()` continua existindo e continua seguro chamar múltiplas vezes (o guard `_autopsyPerformed` permanece). Apenas deixa de ser recomendado para esse uso.

## 8. Notas módulo-por-módulo

### 8.1 `SIMUT.ino`
OK. O comentário sobre `watchdog_enable` só depois do primeiro `loop()` é valioso; preservar. Única sugestão: mover o comentário para dentro do `if (!_wdtStarted)` para ser auto-documenting.

### 8.2 `AppManager`
- Excelente orquestração de boot (linhas 61–449). Preservar na refatoração.
- `loop()` tem priority-scheduling sofisticado — `isUserInteracting()` gate em telemetria, `_pendingTimeSync` oportunístico. Correto, só comentar mais claramente o *porquê* da ordem (§6.5).
- `graph cache` em 2 níveis (preload 7d + ranges do sensor aberto) é elegante; precisa de testes de invalidação após time-sync (já tratado em `handleTimeSync`).

### 8.3 `DisplayManager`
- Hard-reset de Core 1 (`multicore_reset_core1()`) é a solução de último recurso; comentar no header que isso tem custo de ~50 ms de TFT branco. (*Está* no comentário inline, promover ao header.)
- Touch handler e keypad scrambled merecem seu próprio arquivo (§5.2).
- `DICTIONARY` inline é grande (~140 strings × 2 idiomas). Fica fácil de traduzir se mover para `DisplayManager_I18n.cpp`.

### 8.4 `StorageManager`
- Duplo-banco + CRC32 é robusto. Migrações v12→v15 preservam dados — excelente.
- Macro `FLASH_OP` (linha 33) é boa. Documentar que **não pode** ser usada fora de métodos que já seguram `_heavyTaskLocked` — caso contrário, risco de reentrância.
- `deriveKeystream` é HKDF-Expand-like; não chame de “XOR simples”. Documentar equivalência com RFC 5869.

### 8.5 `WebManager`
- `jsonExtractStringValue` (linha 64) foi o fix de um bug real (templates salvos como 2 chars). Tem comentário bom; manter.
- Rate-limit, nonces, sessions, RBAC estão todos corretos.
- `handleApiHistoryData` é grande — candidato a extrair `renderHistoryJson(File&, ...)` para um helper.

### 8.6 `TelemetryManager`
- `TelemetryGuard` com timer repetitivo + teto `WDT_FEED_MAX_WINDOW_MS` é uma das melhores soluções de WDT-during-TLS que já vi em Arduino. Preservar.
- Backoff exponencial com supressão de log após `BACKOFF_MAX_STREAK` + heartbeat 1×/h é proporcional. Preservar.

### 8.7 `NetworkManager`
- Comentário `F-IP-FIX` (linhas 62–67) é salva-vida. Preservar ao pé da letra.
- `setProvisionalTime` + `_provisionalActive` + callback `_timeSyncCb` é um padrão bonito de *virtual RTC*. Documentar no header.

### 8.8 `LogManager`
- Singleton pelo `instance()` é pragmático. RAII `WdtWindow` e `TraceScope` são ótimos.
- `writeConsole` com chunking de 200 bytes para BT é detalhe importante; preservar.
- Single regress: re-init via `begin()` em runtime (§5.6).

### 8.9 `CommandManager`
- Parser manual por `t0/t1/t2/...` (linha 183–188 etc.) é OK para a quantidade de comandos atual, mas vai escalar mal. Sugestão *opcional*: tabela de despacho `{string, DemandType, argCount}`. Não urgente.

### 8.10 `SensorManager`, `SoundManager`, `MetricsManager`, `Themes`, `Bluetooth`
- Amostragem leve; sem red flags visíveis nos headers. Validação detalhada fora do escopo deste documento.

### 8.11 `TftWithOffset`, `TouchPriority`, `SystemUtils`
- Pequenos e corretos. `TouchPriority::isActive()` com fail-safe para provider nulo é boa prática.

## 10. Padrão de código esperado em PRs derivados

O autor exige, **em qualquer função que for modificada ou criada**:
1. Docblock Doxygen-style (`@brief`, `@param`, `@return`) quando é público.
2. Comentário inline explicando o *porquê*, não o *o quê*.
3. Indentação 4 espaços; blocos sempre com chaves; sem `goto`; RAII quando possível.
4. Sem alocação dinâmica em hot-path; preferir stack/`char[]`.
5. `timeReached/timeSince/timeRemaining` em qualquer comparação com `millis()`.
6. `static_assert` em qualquer struct empacotado.
7. Sem `Arduino String` em logger/ISR/timer.

**Exemplo de patch mínimo no estilo esperado** (ilustrativo, para uma correção trivial — idêntica estética para mudanças grandes):

```cpp
// ============================================================================
//  PATCH §5.7 — Remove docblock obsoleto em isValidHistoryFileName.
//  Arquivo:  SIMUT/SystemUtils.cpp
//  Função:   bool isValidHistoryFileName(const char* name)
//  Motivo:   O primeiro docblock referencia ".csv" (formato abandonado em
//            v3.11+; hoje histórico é binário em ".bin"). O segundo docblock
//            já descreve o comportamento correto. Ferramentas de doc pegam
//            o primeiro — risco documental, sem impacto funcional.
//  Preservação: nenhuma função removida, nenhuma semântica alterada.
// ============================================================================

/**
 * @brief  Valida nome de arquivo de histórico binário.
 * @param  name  Nome do arquivo (sem path). Aceita-se apenas "YYYYMMDD.bin"
 *               (12 caracteres exatos). Previne que `enforceStorageLimit()`
 *               apague arquivos alheios ao schema do projeto.
 * @return true  se o nome casa com o schema.
 * @return false se nulo, tamanho != 12, 8 primeiros chars não são dígitos,
 *               ou extensão != ".bin".
 */
bool isValidHistoryFileName(const char* name) {
    if (!name) return false;

    /* Tamanho fixo: "YYYYMMDD.bin" = 12 chars. Comparação via strlen-like
     * manual evita incluir <cstring> só para isso. */
    int len = 0;
    for (const char* p = name; *p; ++p) ++len;
    if (len != 12) return false;

    /* Primeiros 8 chars devem ser dígitos (YYYYMMDD). */
    for (int i = 0; i < 8; ++i) {
        if (!isdigit((unsigned char)name[i])) return false;
    }

    /* Extensão literal ".bin" — não case-insensitive de propósito
     * (LittleFS preserva case). */
    return (name[8]  == '.' &&
            name[9]  == 'b' &&
            name[10] == 'i' &&
            name[11] == 'n');
}
```

## 11. Protocolo de colaboração IA avaliadora ↔ humano

O autor exige que **nenhuma função seja perdida em refatoração**. Este protocolo garante isso:

1. **Antes de qualquer refatoração estrutural** (§5.1, §5.2, §5.4):
   - IA gera `docs/symbols_inventory_before.md` listando, por arquivo, todo símbolo público (função, classe, enum, struct, macro, constante inline) com assinatura completa.
   - Humano aprova.
2. **Durante a refatoração:**
   - IA propõe patches pequenos (≤300 linhas de diff) por PR.
   - Cada PR traz no corpo uma seção *“Funções preservadas”* listando uma-a-uma as funções que existiam antes e continuam existindo depois, com caminho atualizado.
3. **Após a refatoração:**
   - IA gera `docs/symbols_inventory_after.md`.
   - `diff --brief before after` precisa ser vazio *em termos de símbolo*; só caminhos de arquivo mudam.
   - Humano valida, binário é flashado em hardware alvo, smoke test manual (boot, conexão wifi, tela dashboard, 1 gravação de histórico, 1 upload telemetria).

Critério de falha explícito: **qualquer função desaparecer do inventário sem justificativa aprovada aborta o merge**.
