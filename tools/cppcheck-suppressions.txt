# cppcheck-suppressions.txt — the checks the static-analysis gate does NOT run.

# Read tools/run_cppcheck.sh first: it explains which severities are enabled
# and why. This file is only for findings that are enabled but that cppcheck
# cannot get right on this target. Every entry states what was measured.

# Site-specific false positives do NOT belong here. They are suppressed
# inline, next to the code, with a comment explaining the specific reason
# (--inline-suppr). Grep for "cppcheck-suppress" under src/ to see them all.

# Adding an entry here disables a check across the whole tree. Do it only
# when the check can produce nothing but false positives on this target.

# Format trap: a line holding nothing but "#" makes cppcheck 2.11 abort with
# "Failed to add suppression. No id." — it strips the comment and then tries
# to parse what is left. Separate blocks with an empty line, not a bare hash.

# --- uint32_t is `unsigned long` on this target, and cppcheck cannot say so.
# arm-none-eabi-gcc reports __UINT32_TYPE__ as `long unsigned int`, so `%lu`
# is the correct specifier for a uint32_t here. cppcheck models uint32_t from
# the platform's integer sizes alone; with int == long == 4 bytes it always
# picks `unsigned int` and flags every correct `%lu` in the tree. There is no
# platform file that expresses the difference.

# Format strings are still gated: the firmware builds with -Wall (see
# pico_base in platformio.ini), so -Wformat runs over the real types with the
# real compiler on every `pio run -e pico_w_release`. That is the authority
# here; this check could only ever add noise on top of it.
invalidPrintfArgType_uint

# --- Managers are file-scope objects, so the C runtime zeroes them.
# `AppManager app;` (src/main.cpp) and the DisplayManager instance live in
# .bss, which is zero-filled before any constructor runs; both then do their
# real setup in begin(), not in the constructor. cppcheck reports every
# member the constructor does not touch — 37 of them, none reachable as
# indeterminate. Members of stack- or heap-allocated structs are a different
# story and stay checked: that is uninitStructMember, which is left enabled
# and which found the CliDemand gap this gate was added with.
uninitMemberVar
uninitMemberVarPrivate

# --- memset(0) on a struct holding floats.
# Portability warning for platforms where all-zero bits is not 0.0f. This
# target is IEEE-754 (arm-none-eabi, -mfloat-abi=softfp on RP2040), where it
# is, and the structs involved (GraphDataPackage, the dashboard state) are
# cleared exactly to get zeroes.
memsetClassFloat

# --- Headers cppcheck cannot see.
# The Arduino core, the Pico SDK and the pinned libraries are not on the
# include path of a standalone cppcheck run, and putting them there costs
# minutes for no findings. Missing system headers are reported, not resolved.
missingIncludeSystem
